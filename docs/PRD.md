# Miharashi — PRD

版: 0.3 / 作成日: 2026-10-11 / 更新: 2026-10-15 / 状態: 初期要件(基準)。実装の現状は [§12](#12-実装状況2026-10-15)

## 1. プロダクトの目的

Linuxサーバーに接続したモニターを、システム状態・AIエージェント状態・写真を表示する専用画面にする。テンキーだけで操作でき、文字・画像・グラフを同じ画面に配置する。

Rustを中心に実装し、LinuxのDRM/KMSへ直接出力する。共通のオフスクリーンレンダラーを先に作り、実機がなくてもPNGとヘッドレステストで画面を確認できるようにする。

対象はDRM/KMSに対応するLinux環境。CPU/GPUの型番、GPUメーカー、搭載メモリ容量、デバイス番号は固定しない。単一GPUと複数GPUの両方を想定し、表示先と監視対象を設定で選べる設計にする。複数GPUで表示と計算を分担する構成も、利用例のひとつとして扱う。

## 2. 要件の根拠と文書の扱い

仕様の基準は、ユーザーが明示した実装依頼と、その後の「実装前にPRD・LP・設計書を作成」「指定フォルダを使用」「LPに画面構成と仮想FAQを含める」「Miharashiを採用」「特定ハードウェアに依存する記載を外す」という依頼である。

参照会話のライブラリ案は検討材料として扱う。本書の設計上の仮定やLPの例示値は、ユーザーの追加指示や実測値を意味しない。

| 区分 | 内容 |
|---|---|
| ユーザー指定 | Rust、Linux直接DRM/KMS、Taffy、tiny-skia、cosmic-text、Plotters、image、evdev、3画面、共通RGBA、テンキー、非同期収集、設定、rootでのアプリ常駐を前提にしない運用 |
| 設計上の提案 | libseatによるseat管理、watch channel、履歴の上限、センサー・エージェントの状態モデル、ワークスペース分割 |
| 未確定 | 対象ディストリビューション、解像度、モニター配線、実際のDRMノード、各エージェントの連携方法、写真素材 |

## 3. 対象利用者と利用場面

- 自宅や小規模環境のLinuxサーバー運用者が、離れた場所から負荷や異常を確認する。
- LLMを動かす運用者が、表示用GPUと推論用GPUの状態を見分ける。
- 画面を拡張する開発者が、外部サービスの接続やDRM実機を用意せずにUIを作る。
- 普段は写真を表示し、必要なときに監視画面へ切り替える。

## 4. 成功条件

1. 全画面を同じRGBAレンダラーで生成し、PNG出力とDRM出力で描画内容を共用する。
2. X11・Wayland・ウィンドウマネージャー・端末エミュレーターをアプリの動作依存に含めない。
3. NumLock状態に左右されない4/6/0/5操作を提供する。
4. モック・未取得・古いデータ・実測値を区別して表示する。
5. アプリを一般ユーザーで実行し、seat無効化時にDRMと入力へのアクセスを停止できる。
6. 実機で検証できなかった範囲をREADMEに明記する。

## 5. 画面構成

2026-10-15 追記: 実装では 5 画面(`status`・`photo`・`room`・`aircraft`・`agents`)になった。室内環境と天気・航空機の画面は
この PRD の後に追加した要件で、構成は[画面の全体構成](DESIGN-screens.md)に記載する。以下の 01〜03 は初期要件として残す。

### 01 システム監視

| 領域 | 内容 |
|---|---|
| ヘッダー | ホスト名、画面名、日時、LIVE / MOCK / STALE、表示バックエンド |
| サマリー | CPU使用率、GPU使用率、メモリ使用量、VRAM使用量 |
| 補助情報 | CPU/GPU温度、取得できる電力、GPUの用途と識別情報 |
| 時系列 | CPU・選択したGPUの履歴。未取得区間を欠損として表示 |
| 詳細 | データの取得元、最終更新、センサー名、表示デバイスと監視対象GPUの識別 |
| フッター | テンキー操作ガイド |

CPU/GPUの電力は別の値として扱う。未対応センサーにはN/Aを表示し、システム全体の電力と誤認させない。

### 02 エージェント監視

2026-10-15 追記: 以下は初期のモック案。Hermes 連携中止後、T3 サーバーを取得元とする
[新しい概要設計](DESIGN-t3-agent-monitor.md)にまとめた。新案は操作不要のカードボード 1 枚とし、
詳細画面は設けない。新着・変更時にカードを中央へ自動表示する。#46 で `agents` 画面として実装した(既定は無効)。

| 領域 | 内容 |
|---|---|
| ヘッダー | エージェント画面、Adapter種別、状態の取得時刻 |
| 一覧 | 名前、状態、作業の短い説明、最終更新 |
| 状態集計 | 稼働中、待機、応答待ち、異常、オフラインの件数 |
| 詳細 | 選択したエージェントの状態、取得元、補足メッセージ |
| フッター | 画面切替と詳細操作 |

初期AdapterはHermes・OpenClaw・Codex・Claude Codeの例示データを返す。実際の製品との接続は未実装として表示する。個別連携は、このAdapterを交換して追加する。

### 03 フォトフレーム

| 領域 | 内容 |
|---|---|
| 背景 | 設定したJPEG/PNG写真を画面にフィット |
| オーバーレイ | 日時、任意の短い文章、CPU/メモリ等の小さな状態表示 |
| 詳細 | ファイル名、表示モード、データの鮮度 |
| エラー時 | 写真未設定・読込失敗を示すプレースホルダー |

MVPは指定した1枚の写真を表示する。スライドショーの順序管理、クラウド写真連携、EXIF編集は後続の検討とする。

2026-10-15 追記: 実装では GEOFRAME の写真フィードを旅・季節ごとに流し、切り替わりに地図つきのカードを挟む(#25)。

## 6. 統一操作

| 操作 | 意図 | NumLockオフ時の対応 |
|---|---|---|
| テンキー4 / 6 | 前後の画面へ循環移動 | 対応するkeypadコード、Left / Right |
| テンキー0 | 画面メニューを開閉 | keypadコード、Insert |
| テンキー5 | 画面ごとの詳細を開閉・確定 | keypad中央コード、対応するClear/Beginコードがある環境 |
| 4 / 6（メニュー中） | 選択項目を前後へ移動 | 同上 |
| 5（メニュー中） | 選択画面へ移動 | 同上 |
| Escape（開発時） | オーバーレイを閉じる。閉じていれば終了 | Escape |

キーの押下を操作単位にし、画面切替では自動リピートを無視する。USBテンキーの実際のキーコードは対象機で確認する。

2026-10-15 追記: 実装では 4/6 = 画面の巡回、8/2 = 画面の中の前後(写真・注目する機体)、5 = 画面の中の決定、0 = メニュー(#40)。
操作パネル(Echo Show 5)からも同じ操作と画面の直接選択ができる。Esc/q の終了は運用中も有効のまま(`Restart=always` で戻る)。

## 8. 非機能要件

- オフスクリーン経路はLinux以外の開発ホストでもコンパイル可能にする。Linux固有機能はtarget/featureで分ける。
- 初期オフスクリーン解像度は1280×720を提案値とし、1920×1080等へ変更可能にする。実機表示では選択したKMSモードに合わせる。
- センサー欠損・ファイルエラー・Adapter停止で、画面全体をクラッシュさせない。
- 履歴とイベントキューに上限を設け、古い収集結果を無制限に溜めない。
- 写真デコード・グラフ生成・描画時間とメモリ使用量を計測し、対象機で更新頻度を調整する。性能値は検証前に保証しない。
- ログに認証情報、エージェントの会話全文、写真の内容を記録しない。
- メニューは文字と色を併用して状態を示し、色だけに依存しない。

## 9. MVPの段階と受け入れ条件

### M0 — 仕様と画面案（今回の作成物）

- PRD、技術設計書、LPを指定フォルダに保存する。
- LPに3画面の構成と仮想FAQを含める。
- LPの例示値と、実装・実機検証が未完了であることを明示する。

### M1 — ソフトウェアレンダラー

- Rustワークスペースのコンパイルが通る。
- 3画面をPNGとして生成でき、日本語・画像・グラフ・重ね合わせを確認できる。
- 設定、画面遷移、キー正規化、寸法/画素形式、欠損データ、画像読込失敗をヘッドレスで検証する。
- モックAdapterと実データの状態が表示上も区別される。

### M2 — Linux実機統合

- 設定または自動検出で選んだ表示デバイス・コネクターを使い、DRM/KMSのみで表示できる。
- 一般ユーザーのプロセスがlogindまたはseatdからデバイスを受け取れる。
- NumLockオン/オフ、VT往復、正常終了、再起動時の動作を対象機で確認する。
- 表示先と監視対象GPUを別々に設定できる。同一デバイスの利用と、複数GPUで用途を分ける構成を確認する。
- DRMが利用できない状態でもPNG/オフスクリーン経路が使える。
- systemd起動とSSH経由のログ確認・再起動ができる。

### M3 — 個別連携と運用改善

実際のエージェントAdapter、GPUセンサー対応の拡張、モニターホットプラグ等は、データ源と対象機の仕様を確認して追加する。

## 10. 対象外

エージェントの実行・停止、LLMモデル管理、遠隔Web管理画面、外部へ公開するAPI、動的Rust ABIプラグイン、マルチモニター合成、OSイメージの自動配布は今回の初期実装に含めない。
