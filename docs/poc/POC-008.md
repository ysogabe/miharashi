# PoC-008 VRM を画面に載せる(Issue #71 B)の実機確認と計測

目的: 写真画面・Agent 画面の脇に VRM のキャラクターを載せる組み込み([#71](https://github.com/ysogabe/miharashi/issues/71) の B。タスクは `docs/vrm-integration/tasks.md`)を、実機(内蔵 GPU、2560x1080)で動かして、描画の速さ・メモリ・アラートやメニューとの重なり・失敗時の振る舞いを確かめる。設計は [Screen Plugin API v2](../DESIGN-screen-plugin-v2.md)(§2〜§4、§9〜§11)、描画の単体スパイクは [POC-006](POC-006.md)、画面に 3D を貸す口の確認は [POC-007](POC-007.md)。

> **この文書の読み方**: 数字は 2026-10-19、Ryzen 7 9700X の内蔵 GPU(Radeon raphael、Mesa 25.0.7、GLES 3.2)、29UM59-P(HDMI-A-1)での値。**画面の絵は目で見ていない**(人が画面の前にいない状態での計測)。アラートやメニューが体の手前に出ることは、オフスクリーンの PNG とテストで確かめた。モデルはリポジトリに置かない(ニケちゃんは同梱禁止)。

## 作ったもの

- `miharashi-vrm`: `VrmScene`(`GlScene` の実装)。モデルの解析は別スレッド、GL への転送は最初の `draw`。モデルが無い・壊れているときは 3D なしで続ける。B の前の宿題(sparse accessor の stride の検査、SpringBone のコライダーの添字、関節 × コライダーの上限)も済み。
- `miharashi-app`: `WithScene<S: Screen>`(`app/screens/with_scene.rs`)。内側の画面(写真・Agent)に委譲して、結果を `Composite::Gl` に包む。`id`・操作・巡回は内側のまま、`needs_gl() = false`。
- 設定 `[vrm]`(既定は無効)。使い方は [USAGE.md](../USAGE.md) の `[vrm]`。
- 覆われているあいだ(アラート・メニュー)は VRM の時計を止め、継続描画にしない(8296e41)。

## 試験の条件

- 2560x1080、60Hz、VRM はニケちゃん(VRM 1.0、81,647 頂点、16 テクスチャ)、位置は左 1/3、30fps。
- 試験用の設定は本番の設定の写しで、変えたのは次の点だけ: `[screen_power]` を外す、`seat = direct`、巡回なし、`stats_interval_secs = 7`。
- 計測は 1 秒ごと: iGPU は `gpu_busy_percent`、CPU はプロセスの utime+stime(1 コアを 100%)、VRAM+GTT は `mem_info_vram_used` + `gtt_used`。画面の切り替えとメニューは操作パネルの API(`screen` / `key menu`、どれも 204)で行った。
- 終わったあと本番の設定に戻した。全段階でプロセスは落ちなかった。

## 計測結果

### 1 回目(2026-10-19 15:51〜16:13 JST)

| 場面 | iGPU | CPU | VRAM+GTT (MiB) | RSS 最大 (MB) | 描画 |
|---|---|---|---|---|---|
| VRM なし・写真 | 0.9% | 0.5% | 129〜225 | 268 | |
| VRM なし・Agent | 0.9% | 1.5% | 179〜201 | 307 | |
| 写真 + VRM | 11.0% | 2.5% | 221〜322 | 334 | 30fps、遅れ 0 |
| Agent + VRM | 17.2% | 3.6% | 325〜339 | 497 | 30fps、遅れ約 4%(206 フレーム中 8) |
| Agent + VRM + メニュー | 9.2% | **34.9%** | 335〜346 | 517 | **15fps、全フレーム遅れ**(render 22ms / present 19ms) |
| 3 秒ごとに写真・Agent・状況を 60 回切り替え | 6.7% | 2.1% | 335〜434 | 518 | |
| 切り替えのあと、状況画面(VRM は非表示) | 0.0% | 0.8% | 350 で一定 | 518 | |
| Agent + VRM + アラートのデモ(地震、30 秒後に災害) | 5.5% | **35.9%** | 247〜267 | 367 | 15fps |
| `renderer = cpu`・写真 / Agent | 0% | 3.5% / 6.7% | 47 | 158 / 203 | VRM を載せず、モデルも読まない |
| 壊れたモデル(先頭 3 MB で切ったもの)・写真 / Agent | 0% | 0.5% / 1.2% | 144〜213 | 246 | 元の画面のまま |

- 壊れたモデルは、ログに 1 回ずつ `vrm: モデルを読めない: glb を読めない: could not completely read the object(3D なしで続ける)` と出て、元の画面で動き続けた。
- 切り替えのあと、VRAM+GTT は 350 MiB で一定。増え続けてはいない。
- メニュー・アラートの表示中は、下地が `Composite::Canvas` になる。VRM が動くあいだ、全画面の CPU 描画(約 22ms)と転送(約 19ms)が 30fps で毎フレーム走って間に合わず、ログに `anim: 遅れ 66.7ms` が続いた(アラートは最長 5 分出る)。これが CPU 35% の原因。

### 修正後の再計測(2026-10-19 16:19〜16:25 JST)

覆われているあいだは VRM の時計を止める修正(8296e41)のあとで、同じ条件で測り直した。

| 場面 | iGPU | CPU | 描画 |
|---|---|---|---|
| Agent + VRM | 12.0% | 3.1% | 30fps |
| Agent + VRM + メニュー | 0.0% | **4.5%** | 約 1.2fps(時計などの更新だけ。render 27〜43ms) |
| メニューを閉じたあと | 11.6% | 2.9% | 30fps に戻る |
| Agent + VRM + アラート | 0.0% | **4.5%** | 約 1.2fps(render 33ms) |

覆われている間の CPU は 35% 前後から 4.5% に下がり、閉じれば 30fps に戻る。

### 初期ロード時間(T2 で測った値)

- モデルの解析は別スレッドで約 60ms。
- GPU への転送は最初の `draw` で約 23ms。以後は 1〜2ms。
- 読み込みは、その画面が最初に表示されたときに始まる。

### region の見た目(PNG で確認)

- **center**: Agent 画面の拡大したカードを体が隠す。
- **right**: 写真画面の右 1/3 にある時計・日付を隠す。Agent 画面では右端の列を隠す。
- **left(既定)**: 身振りの手の先が領域の右端で切れる。`REACH_FRAC` は 0.4 以上でないと効かず、その値では顔が小さくなるので 0.0 のまま。

結論: 既定は left のままにする。

### 12 時間試験(T5、2026-10-19 18:06〜10-20 06:06 JST)

本番の設定に `[vrm]`(写真と Agent、left、30fps)を足し、1e7a797 を本番として動かした。記録は 10 秒ごと(4,376 点)。表示はほぼ写真(巡回のうち写真 約 83%、Agent 約 8%)。

| 項目 | 結果 |
|---|---|
| 停止・再起動 | なし(同じプロセスのまま 15 時間以上) |
| CPU(1 時間ごとの平均) | 2.45〜2.54%。時間がたっても変わらない |
| iGPU(1 時間ごとの平均) | 8.7〜13.7%(全体 約 12%) |
| RSS | 開始 1 時間後 430.8 MB → 12 時間後 432.2 MB(+1.4 MB) |
| VRAM+GTT | 1 時間目以降 332〜431 MiB の幅で上下し、増え続けない |
| VRM の遅れ | 1,229,167 フレーム中 7,441(0.6%)。遅れは最大 50 ms(1 フレーム落ち)、最悪フレーム 41 ms |
| ログ | エラーは外部の取得の一時失敗と回復だけ。VRM のエラーなし |

試験のあと、07:17 に消灯し、09:21 に点灯した。点灯後に VRM が動いていること、メニューを開くとメニューが体の手前に出て VRM が止まることは、ユーザーが画面で確かめた。

## 判断

- **タイムアウト解放は要らない**(設計書 §3)。
  - 写真と Agent の両方に載せると、モデルを 2 回読むので、VRAM+GTT は約 +150 MiB、RSS は約 +230 MB になる。
  - 60 回切り替えても増えず、VRM が非表示のあいだも 350 MiB で一定だった。
  - 内蔵 GPU の VRAM+GTT は、全体で 350 MiB 程度に収まる。
- **`base_changed` は入れない**(設計書 §10)。代わりに、覆われているあいだは VRM を止める。CPU は 35% から 4.5% に下がった。覆われているあいだも動かしたくなったら、`base_changed` を入れて、この「止める」判断を外す。
- 既定の region は left のまま。

## 制限事項と後続の Issue

後続の Issue は番号が未定。

- **モデルを 2 つの画面で共有する**: 今は画面ごとに読むので、RSS が約 +230 MB になる。共有すれば約半分になる見込み。
- **手の先が切れる件と、画面ごとに region を選べるようにする件**: 左 1/3 だと身振りの手の先が切れる。`REACH_FRAC` では解決しないので、領域の取り方を変える必要がある。
- **Agent + VRM のときの遅れ約 4%**(206 フレーム中 8)。
- 覆われているあいだの VRM は止まる(体は最後の姿勢のまま、アラート・メニューの奥に見える)。
- **実機での大きさと配置**: 動いていることは確かめたが、モニター上での大きさと配置が適切かは、まだ確かめていない。
- **確かめていないこと**: アラートが体の手前に出ることの実機の目視(PNG とテストで代えた)。
