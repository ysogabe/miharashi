Echo Show の「操作パネル」([panel/DESIGN.md](panel/DESIGN.md))とは区別する。

## 2. 画面の一覧

登録順が 4/6 キーの巡回順と、操作パネルの画面一覧(`/api/v1/status` の `screens`)の順になる。`id` は
操作パネルとの約束なので、決めたら変えない。

| 順 | id | 題名 | 中身 | 画面内の操作(5・8/2) |
|---|---|---|---|---|
| 1 | `status` | STATUS | サーバーの状態(OVERVIEW / DETAILS の 2 ページ) | 5 = ページ切替 |
| 2 | `photo` | PHOTO FRAME | 写真(旅・季節ごと、カードつき) | 8/2 = 前後の写真、5 = 情報帯の表示切替 |
| 3 | `room` | ROOM & WEATHER | 室内環境(HA)と天気(気象庁)、自宅の市町村の警報・注意報 | 5 = 週間予報 ↔ 時間ごと(将来)。当面なし |
| 4 | `aircraft` | AIRCRAFT | 受信機中心のレーダーと、いちばん近い機体の諸元 | 8/2 = 注目する機体を切り替え、5 = 注目を「いちばん近い機体」に戻す |
| 5 | `agents` | T3 AGENTS | T3 のプロジェクト・スレッドのカードボード(#46、[設計](DESIGN-t3-agent-monitor.md))。`[agents] enabled = false` なら登録しない | なし(操作不要) |

- 左: 室内のセンサー 6 枚(温度・湿度・CO₂・VOC・気圧・玄関の温湿度)。値と過去 24 時間の折れ線。

### 2.2 航空機(`aircraft`)

画面は #27 のもの(左半分にレーダー、右半分に諸元と一覧)をそのまま使い、写真画面から切り離す(S3 で実装、2026-10-15)。

- 機体がいないときは、レーダーと「半径内に機体はありません」、受信機の状態(最終受信時刻・受信機数)を出す。
- 8/2 で注目する機体を近い順に切り替える(レーダー上も強調を移す)。5 で「いちばん近い機体」に戻す。
- 毎秒描き直す(位置は 5 秒ごとに更新。描画の間は速度と進行方向で位置を進めて、動きを滑らかにする)。

## 3. 全体の構成

```mermaid
flowchart LR
    subgraph 取得(各自のスレッド)
        SYS[system: CPU/GPU/電力]
        FEED[photos: GEOFRAME の写真フィード]
        ENV[env: HA の室内センサーと 24h 履歴]
        WX[weather: 気象庁の府県予報・週間予報]
        WARN[warnings: 気象庁 r8 の警報・注意報]
        AIR[aircraft: tar1090 + adsbdb]
        QK[quake: 気象庁の地震情報]
        HA[screen_power: HA の在宅・画面モード]
    end
    SYS & ENV & WX & WARN & AIR --> W[World: 画面が読む共有データ]
    WARN -- 特別警報・土砂災害危険警報 --> AL[アラート層]
    QK --> AL
    FEED --> PH[photo 画面が所有]
    W --> SM[ScreenManager]
    PH --> SM
    AL --> SM
    ROT[自動巡回] --> SM
    KEY[テンキー / 操作パネル] --> SM
    SM -- 表示中の 1 画面 + 重ね描き --> RT[runtime: DRM/KMS・GLES]
    HA --> RT
```

- **runtime** は今のまま(`trait App` だけを知る)。画面の電源(`screen_power`)も runtime に残す。
- **ScreenManager** が `App` を実装する。画面の登録・巡回・メニュー、自動巡回、アラート層の重ね描き、
  操作パネルへの状態(`panel_view`)を受け持つ。今の `KioskApp` の中身を画面ごとに分けて移す。
- **Screen** は 4 つ(§2)。写真フィードのように画面だけが使う資源は画面が持つ。
- **Provider**(取得)は自前のスレッドで取り、`World` の自分の領域に最新値を写すだけ(ブロックしない)。
  非表示の画面のデータも取り続ける(切り替えた瞬間に出せるように)。
- **アラート層**は画面ではない。地震・災害のアラートは表示中の画面に関係なく最前面に重ね、
  画面が消えていても点ける(今の `wants_screen`)。

### 3.1 World(共有データ)

| 領域 | 書く Provider | 読む画面 | 更新間隔 |
|---|---|---|---|
| `clock` | ScreenManager | 全画面 | 毎 tick |
| `system` | system(今の `data.rs`) | status | 1 秒 |
| `photo_feed` | photo 画面 | status(HEALTH) | 変化時 |
| `env` | env | room | 値 60 秒、24h 履歴 10 分 |
| `weather` | weather | room | 30 分(気象庁の発表は 1 日 3 回) |
| `warnings` | warnings | room(帯)、アラート層 | 60 秒(ETag で 304) |
| `aircraft` | aircraft | aircraft | 5 秒 |

- `warnings` は今の `disaster.rs` を分けて作る: 取得と解析(自宅 50km の市町村の全種類の発表)を Provider にし、
  「新しく出た特別警報・土砂災害危険警報」の判定とアラート送信はその上に残す。room 画面は自宅の市町村の分だけを読む。
- `aircraft` は今の `aircraft.rs`(#27)の `Shared` をそのまま `World` の領域にする。

## 4. 画面の切り替え

### 4.1 手動

[DESIGN-screen-interface.md §3.1](DESIGN-screen-interface.md) の決定どおり、**4/6 = 画面の巡回、0 = メニュー、
5・8/2 = 画面の中の操作**にする。今の「写真画面で 4/6 = 前後の写真、5 = 状況画面へ」は変わる
(写真の前後は 8/2 へ)。操作パネルからは `POST /api/v1/screen {"id": "room"}` で直接選べる(panel P3)。

### 4.2 自動巡回(無人のとき)

無人の試験や日常運用で全画面が表示されるよう、設定した順番と時間で画面を巡回する。

```toml
[rotation]
enabled = true
# 画面 id と表示する秒数。上から順に繰り返す
steps = [
  { screen = "photo",    secs = 600 },
  { screen = "room",     secs = 60 },
  { screen = "photo",    secs = 600 },
  { screen = "aircraft", secs = 60, skip_if_empty = true },
  { screen = "status",   secs = 30 },
]
# キー・操作パネルで操作したら、この秒数のあいだ巡回を止める
pause_after_input_secs = 300
```

- `skip_if_empty`: 航空機の画面は、半径内に機体がいなければ飛ばす(夜間に空のレーダーを出し続けない)。
- 操作した後は `pause_after_input_secs` のあいだ巡回を止め、最後の操作から時間がたったら巡回の続きから戻る。
- 操作パネルから巡回を止めたままにでき、再開もできる(`POST /api/v1/rotation`、#57)。止めたままの間は時間がたっても戻らない。
  止めた状態は保存しないので、キオスクを再起動すると巡回は設定どおり戻る。
- アラートは巡回と関係なく重ねる。アラート中は巡回の時間を進めない。
- 写真画面に戻ったときは、続きの写真から(旅の途中で抜けても、戻ると同じ旅の続き)。
- 状態ログに `screen=<id>` と `rotation=on/paused/off` を出す(`tools/soak_summary.py` が読めるよう id にそろえる)。

### 4.3 写真画面の中の演出

- 旅・季節のカード(#25)は写真画面の中に残す。
- 写真の合間の航空機画面(#27)は、航空機を独立した画面にしたときに廃止する(設定 `[aircraft] every_photos` もなくす)。→ S3 で廃止した。古い設定ファイルの `every_photos` / `show_secs` は読むだけ読んで警告を出す。

## 5. 描画と負荷

| 画面 | 描き方 | 描き直す時 |
|---|---|---|
| status | CPU の Canvas(全面) | 1 秒 |
| photo | 写真は GPU で合成、時刻などの重ね絵だけ CPU(PoC-005) | 写真の切替・フェード中・重ね絵の変化 |
| room | CPU の Canvas(全面) | 時計の分が変わった時と、データが更新された時 |
| aircraft | CPU の Canvas(全面) | 1 秒(位置を補間) |
| アラート層 | CPU(写真画面では重ね絵に描く) | 変化時 |

- 全面を CPU で描く画面は 2560×1080 で 1 枚あたり数 ms〜十数 ms(今の状況画面の `render_ms` と同程度)。
  iGPU の負荷は Canvas の転送と合成が主になる。地図の都道府県ポリゴン(航空機・カード)は毎回描くと重いので、
  背景の地図は画面サイズごとに 1 回だけ描いて保持し、機体や文字だけを毎秒重ねる。
- 12 時間試験の結果(10/14)を見て、巡回の秒数と描き直す間隔を決め直す。

### 7.1 S4 の実装(2026-10-15)

§3 の案から変えたところと、決めたこと。

- **`World` を通さない**: S3 の航空機と同じく、取得のスレッドが持つ `Arc<Mutex<..>>` を画面が直接読む
  (`env::Shared`・`weather::Shared`・`disaster::HomeShared`)。読む画面が 1 つだけなので、`World` の領域にする利点がまだない。
- **warnings は disaster のスレッドが兼ねる**: 気象台のファイルは災害アラートと同じものなので、`disaster.rs` を分けずに、
  同じ取得で自宅の市町村の全種類の発表(注意報〜特別警報)を `HomeWarnings` に写す。`[alerts] disaster = false` なら帯は
  「警報の取得は無効です」になる。
- **自宅の市町村**: HA の自宅の位置 → 国土地理院の逆ジオコーダーの市区町村コード(5 桁)→ area.json の class20
  (`13101` + `00`。無ければ同じ 5 桁で始まる最初のもの)→ class15 → class10(予報の地域)→ 気象台。
  予報の地域は `room.forecast_area` で固定もできる。一度引けた市区町村コードは HA の位置と組で
  `/var/lib/miharashi/home.json`(0600)に残し、逆ジオコーダーに届かないときは位置が同じならそれを使う
  (`home.rs`。地震の地方・天気・警報の 3 つで共有する)。位置が変わっていたら使わない。
  災害の取得は、自宅の市町村だけが決まらなかったときも 10 分後に問い合わせ直す。
- **予報の読み方**: 気温は時刻で読む(0 時 = 朝の最低、9 時 = 日中の最高)。11 時・17 時発表の「今日の 0 時」は最高気温の
  写しなので使わない。降水確率は 6 時間ごとの枠に日付でまとめ、過ぎた枠は "--"。週間予報は明日から 7 日で、
  1 日目(明日)の空欄は府県予報で埋める。週間予報の地域は class10 と同じものか府県のもの、気温はアメダスの地点
  (forecast_area.json)で選び、無ければ先頭。週間予報の文は天気のコードから(気象庁の予報ページの表を写した `weather::telop`)。
- **HA の履歴**: `/api/history/period` を 10 分ごとに読み、10 分きざみ(24 時間で 144 点)にならす。HA は変化したときだけ
  記録するので、変化の無い区間は直前の値を引き継ぎ、unavailable の間は折れ線を切る。気圧は `trend_hours` 前との差で
  上昇・下降(±0.5 未満は横ばい)。
- **取得できないとき**: 最後の値を残し、見出しの右に「最終取得 16:20 · HA に接続できません」を黄色で出す。
  一度も取れていなければ「接続しています…」か理由。地域を決める段階で止まった相手は、その相手の名前で出す
  (「国土地理院に接続できません(予報の地域を決められない: …)」。HA なら HA)。
- **描き直し**: 時計の分が変わった時と、取得の版(`FeedStatus.version`)が上がった時だけ。
- **確認**: `miharashi png --live` で実際の HA と気象庁から取った画面を `room-live.png` に出す。
- 室内センサーは 6 枚まで(§8 の「6 枚を超えたら」は未決のまま。7 枚目からは出さず、起動時に警告する)。

### 7.2 S5 の実装(2026-10-15)

- `[rotation]` は §4.2 のとおり。**既定は `enabled = false`**(設定を書かなければ今までどおり手動)。`steps` の既定は §4.2 の案。
- 有効なら `ui.start_screen` ではなく最初の手順の画面から始める。出していない画面(航空機・室内環境が無効)の手順は起動時に捨てる。
- `skip_if_empty` は `Screen::is_empty()` で判断する(航空機の画面は、30 秒以内に取れた半径内の機体が 0 機のとき空)。
  どの手順も飛ばす状態なら、今の画面のまま 1 手順分待ってから見直す。
- 操作(キー・操作パネルの `POST /api/v1/screen`。アラートを閉じるだけのキーも含む)で `pause_after_input_secs` 止め、
  最後の操作から時間がたったら、止めたときの手順の**次の**手順から戻る。
- アラートの間は手順の残り時間を減らさない。メニューは開くキーで巡回が止まる。
- 巡回の切り替えは `keys=` に数えない(状態ログの `keys` は人の操作だけ)。状態ログの末尾に `rotation=on` / `paused`(止めたままなら `off`、#57)。
- 写真画面は表示中だけ次の写真へ進むので、巡回で戻ると続きの写真から出る。
- 焼き付き対策の演出は、対象の画面を続けて `refresh_minutes` 出したときだけ入るので、巡回の手順がそれより短いと入らない
  (画面が切り替わること自体が焼き付き対策になる)。巡回を止めたまま(`off`)にすると、同じ画面を出し続けるので演出が入る(#57)。
- 操作パネルの `/api/v1/status` と SSE に `rotation: {"state": "on" | "paused", "resume_in_s": 240 | null}`(無効なら `null`)を出す(#45)。
  止めたままの `"off"` と `control` は下のとおり(#57)。
  `resume_in_s` は戻るまでの残り秒数(切り上げ)。`PanelView` には戻る時刻だけを持たせ、秒数は `/status` を組み立てるときに計算する(毎秒 SSE を送らない)。
  実行ループは毎秒の tick(再描画の要求)のたびにパネルへ状態を渡す(モニターを消していても。SSE は変わったときだけ)ので、
  止まる・戻るは 1 秒以内に届く。
- `POST /api/v1/display`(モニターの消灯・点灯・自動)では巡回を止めない。止めるのはキーと `POST /api/v1/screen` だけ
  (止めたままにする `POST /api/v1/rotation` は下のとおり)。

操作パネルから巡回を止めたままにする・再開する(2026-10-16、#57):

- 巡回の状態は `on` / `paused`(操作で一時停止中)/ `off`(止めたまま)の 3 つ。
- `POST /api/v1/rotation {"mode": "off"}` で、`on` か `paused` から `off` にする。`off` の間は手順の時間を進めず、画面も切り替えない。
- `off` の間にキーや `POST /api/v1/screen` で操作しても `paused` にしない(`off` のまま)。ここで `paused` にすると、
  止めたあとにキーを押すだけで `pause_after_input_secs` 後に巡回が戻ってしまう。
- `{"mode": "on"}` で、`off` か `paused` から `on` にする。再開したら、すぐ次の手順の画面へ移る(一時停止が明けたときと同じ)。
  `paused` から `on` を送ると「今すぐ再開」になる。今と同じ状態を送っても何もしない(204)。
- この操作そのものでは巡回を一時停止にせず、モニターも点けない(画面は選んでいないので、`/api/v1/display` と同じ)。
  モニターが消えていても反映する。`[rotation]` が無効(または回せる画面が無い)なら 409。トークンとレート制限は `/api/v1/display` と同じ。
- アラートとメニューは今のとおり(`off` でもアラートは出る)。
- `/api/v1/status` と SSE の `rotation` は `{"state": "off", "resume_in_s": null, "control": true}`。`control` は
  `/api/v1/rotation` を受け付けるか(古いキオスクでは無いので、パネルはボタンを灰色にする)。`off` になる・戻るときにも SSE を送る。
  状態ログの末尾は `rotation=off`。
- **止めた状態は保存しない。** キオスクを再起動すると、巡回は設定どおり `on` に戻る。
- **焼き付き対策は各画面の責務とする。** 止めたままにしても自動では再開しないので、巡回は焼き付き対策として当てにしない
  (`[ui]` の `refresh_minutes` / `refresh_screens` など)。
- パネル側のボタンの置き場所は miharashi-panel 側で決める。
