01 / Panel

960×480 の画面に、
押しやすいボタンだけ。

4 / 6 で画面を切替、5 で決定。
8 / 2 / 0 は次の段階で有効に。

LEFT

モニターの消灯・点灯・自動

今の状態(点灯中・消灯中)と、Home Assistant の切り替え(自動 / 常に点灯 / 常に消灯)を表示します。4 / 5 / 6 から離して縦に並べ、押し間違えないようにしています。

CENTER

押した結果が、手元に戻る

ボタンはキーを送るだけ。切り替わった画面名、ページ、写真の何枚目かはキオスクから取り直して表示します。取れなくなれば STALE、15 秒で OFFLINE。

FEEDBACK

音と振動、失敗は赤く

押下音と触覚で応答します。送信に失敗したらボタンが赤く点滅し、勝手に再送しません。長押し確定は使いません。

HEADER

API と Wi-Fi の点灯

キオスクとつながっているか、Wi-Fi があるかを常に表示します。Wi-Fi が戻れば自動で再接続します。

SLEEP

触らなければ消灯

3 分触らなければ画面を真っ黒にしてバックライトを最小に。触れば点灯し、その最初のタッチではボタンを押しません。焼き付き・残像を避けるためです。

BOOT

電源を入れれば操作盤

端末の起動時とアプリの更新時に、自動で前面に出ます。スワイプだけのロック画面より手前に表示します。

02 / Transport

BLE キーボードか、
ネットワーク API か。

同じ条件で並べて比べ、
ネットワーク API を選びました。

A

BLE キーボード(HOGP)

付録に保持
  • Miharashi 側の変更なし。bluez を入れれば普通のキーボードとして evdev に出る(未検証)
  • Echo を BLE 周辺機器にする実装(GATT、Report Map、ペアリング)を新規に書く
  • LineageOS では ROM の変更(priv-app、feature 宣言)と署名鍵の管理が要り、更新のたびに再ペアリングの危険がある
  • 一方向。今どの画面かは手元に出ない。Echo 以外からは使えない
  • ホストに bluez の導入とヘッドレスのペアリング、再起動後の再接続の確認が要る
B

ネットワーク API(Wi-Fi)

採用
  • Echo 側は HTTP クライアントだけ。通常のアプリで済み、ROM の変更も再ペアリングも不要
  • 双方向。画面名、写真の n / N、将来の LLM・エージェント状態を手元に出せる
  • Echo がなくても curl で検証でき、スマホのブラウザーや別の端末からも同じ API
  • Miharashi に小さな待ち受けを足す。既定は無効、トークン、1 インターフェース限定
  • Echo の Wi-Fi の安定性は実機で測る(5GHz の不安定の報告あり)

決め手は 3 つ。Echo 側が普通のアプリで済むこと、手元に状態を出せること、Echo がなくても検証できること。A 案は「やるなら何が要るか」を設計書の付録に残しています。

03 / How it connects

パネルはキーを送るだけ。
画面の論理はキオスクに。

ECHO SHOW 5単体アプリ miharashi-panel大きなボタン、現在画面、モニターの状態。状態は持たない
POST /api/v1/input · display
GET /api/v1/status · events
MIHARASHIpanel スレッドBearer トークン、レート制限、LAN のインターフェースだけで待ち受け
mpsc: KeyPress
RUNTIME実行ループテンキーと同じ入口。DRM / VT / seat は変えない
input_select.select_option
HOME ASSISTANTモニターの手動切り替えauto / force_on / force_off。キオスクがすぐ読み直して反映
API

5 つのエンドポイント

GET /api/v1/status
画面名・一覧、ページ、写真の位置、モニターの状態
POST /api/v1/input
prev / next / select。up / down / menu は次の段階。quit は受け付けない
POST /api/v1/display
モニターを auto / force_on / force_off に
GET /api/v1/events
状態が変わるたびに push(SSE)
GET /api/v1/healthz
認証なしの生存確認だけ
SAFETY

キオスクはコマンドを実行しない

API でできるのはキー操作、モニターの切り替え、状態の読み出しだけ。設定で有効にしない限り待ち受けは立ち上がらず、0.0.0.0 は指定できません。パネルが消えてもキオスクは影響を受けません。

APP

普通のアプリで、別のリポジトリに

priv-app にせず、ROM も変えません。Kotlin で書いた依存ライブラリ無しの小さなアプリで、ソースは miharashi-panel にあります。

05 / FAQ

よくある質問

作っている側が、
聞かれそうだと思った質問です。

なぜ Echo Show 5 なのですか？

960×480 の横長画面が机に置く操作盤にちょうどよく、Android 化すれば普通のアプリが動くからです。Miharashi 専用の単体アプリとして全画面で使い、ほかの用途との同居は考えません。

BLE キーボードにしなかったのはなぜですか？

Miharashi 側の変更がゼロという利点はありますが、Echo を BLE 周辺機器にするには ROM の変更(priv-app、feature 宣言)と署名鍵の管理が要り、更新のたびに再ペアリングの危険があります。手元に状態も出せません。設計書の付録に「やるなら何が要るか」を残しています。

モニターの消灯は、キオスクの中だけで切り替えないのですか？

切り替えません。キオスクが Home Assistant の切り替え(input_select)を書き換えます。こうすると HA の画面とパネルの表示が食い違わず、再起動しても設定が残ります。

キオスクに API を足して安全ですか？

既定は無効で、有効にしても Bearer トークンと LAN の 1 つのインターフェースに限ります。できるのはキー操作、モニターの切り替え、状態の読み出しだけで、コマンドは実行しません。

Echo の Wi-Fi が切れたらどうなりますか？

パネルは STALE、15 秒で OFFLINE を表示し、最後の状態を薄く残したまま再接続を続けます。キオスクは影響を受けません。

Echo が再起動したらどうなりますか？

起動時に自動で前面に出て、/status を取り直します。アプリは状態を持たないので、落ちても同じ表示に戻ります。

操作盤の画面が焼き付きませんか？

3 分触らなければ真っ黒にしてバックライトを最小にします。時間は設定で変えられ、0 にすれば消灯しません。

スマホのブラウザーからも操作できますか？

同じ API なので、ブラウザー向けの小さなページも作れます。今は Echo のアプリだけです。
